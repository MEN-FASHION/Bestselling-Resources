# TREND BANK（前台浏览 + 后台传图 · 真私密版）

一个部署在 **GitHub Pages** 的图片站：

- **前台**（`index.html`）：用户用 **邮箱+密码** 登录后，按分类浏览图片（缩略图懒加载、点击看大图）。近期新增 **趋势专区入口**（`trends.html`）。
- **后台**（`admin.html`）：**管理员**登录后，可 **网页拖拽上传/删除图片**，并管理 **趋势专区** 文件。
- **趋势专区**（`trends.html`）：登录后按 类目 / 月度 / 周度 标签浏览、在线预览趋势 PDF（受控鉴权、防下载）。

**图片真正私密**：所有图片存放在 Cloudflare R2 私有桶中，任何图片请求都必须携带登录令牌、经 Cloudflare Worker 校验后才放行 —— **未登录的人连图片网址都打不开**。

## 一、架构说明

```
GitHub Pages（静态页面）
   ├── 前台 index.html ──┐
   └── 后台 admin.html ──┤
                        ├──► Supabase（只做登录验证 + 图片清单）
                        │       ├── Auth      邮箱密码登录/会话
                        │       └── Database  profiles 角色表 + images 清单表
                        │
                        └──► Cloudflare Worker（图片"守门员"，免费）
                                ├── 校验令牌（问 Supabase：登录了吗？是管理员吗？）
                                ├── 通过才从 R2 私有桶取图/存图/删图
                                └── R2 私有桶（图片文件，任何人无法直接访问）
```

- **Supabase** 只承担 **登录验证 + 数据库清单**（不存图片，不占它的 1GB 存储/5GB 流量）
- **图片文件** 全部放 **R2 私有桶**（免费 10GB、出口流量不收费），由 Worker 鉴权代理

## 二、部署步骤

### 第 1 步：准备好 Supabase 项目（只做登录）
1. 登录 supabase.com，新建项目。
2. 记下 **Project URL** 与 **anon public key**（Project Settings → API）。
3. 填入 `js/config.js` 的 `SUPABASE.url` 和 `SUPABASE.anonKey`。

### 第 2 步：执行数据库初始化
1. 项目 → **SQL Editor** → New query。
2. 打开 `tools/setup.sql`，全选复制运行。
3. 自动创建：`profiles` 表（角色）、`images` 表（清单）、`categories`/`tag_defs`/`site_settings`/`announcements`/`trends`/`recruit_tasks`、`login_logs`（登录设备/IP 记录）等表、安全策略、注册自动建档，以及前台函数 `frontend_list_images`（前台读全部图片）、`frontend_list_used_cats`（前台类目菜单读全部图片类目）、`record_login`（登录记录写入）、`get_last_login_logs`（超管读取最近登录记录）。

### 第 3 步：开启邮箱登录
- 项目 → **Authentication → Providers → Email** 开启，建议关闭 Confirm email。

### 第 4 步：创建管理员
1. 访问站点 `admin.html` → “暂无账号？注册一个”，用你的邮箱注册。
2. 回 Supabase → **SQL Editor** 执行（换成你的邮箱）：
   ```sql
   update public.profiles set role = 'admin'
     where email = '你的邮箱@example.com';
   ```
3. 回站点刷新重新登录，上传功能即开放。

### 第 5 步：创建 Cloudflare R2 桶（图片仓库）
1. 注册/登录 **Cloudflare**（免费）→ 左侧 **R2 Object Storage**。
2. **Create bucket**：桶名填 `images`，**不要选"允许公开访问"**（保持私有）。
3. 记下桶名。

### 第 6 步：部署 Cloudflare Worker（守门员）
1. 左侧 **Workers & Pages** → **Create** → **Worker** → 随便起个名字（如 `gallery-api`）→ Deploy。
2. 进入该 Worker → **Settings → Variables**：
   - 添加 `SUPABASE_URL` = 你的 Supabase Project URL
   - 添加 `SUPABASE_ANON_KEY` = 你的 anon public key
3. **Settings → Bindings** → Add → **R2 Bucket**：
   - 变量名填 `IMAGES`，选择你刚创建的 `images` 桶。
4. 回到 Worker **Edit code**，把本目录 `worker/worker.js` 的**全部内容覆盖**粘贴进去 → Deploy。
5. 记下 Worker 访问地址（形如 `https://gallery-api.你的子域.workers.dev`），填入 `js/config.js` 的 `WORKER_URL`。

> **趋势专区依赖**：新版 `worker/worker.js` 额外提供了趋势文件的上传 / 删除 / 受控预览（`/trend/...`）端点。请务必用最新版 `worker/worker.js`（与趋势相关）整体覆盖部署，否则趋势上传与前台预览会失败。

> **存量图片压缩池依赖**：本版 `worker/worker.js` 额外提供 `/admin/list-imgs`（列出存储全量图片 key + 大小）与 `/admin/overwrite`（按原路径覆盖写回压缩后的 WebP）两个管理员端点，供超管面板「存量图片压缩池」使用。请务必用最新版 `worker/worker.js` 整体覆盖部署并重新发布，否则后台压缩池无法加载图片清单、压缩写回会失败。

### 第 7 步：部署到 GitHub Pages
1. 把 `gallery-site` 目录所有文件推送到 GitHub 仓库。
2. 仓库 → **Settings → Pages** → Deploy from a branch，分支 `main`，目录 `/ (root)`。

## 三、使用说明

**前台（访客）**
- 打开站点，邮箱注册/登录后进入画廊；顶部切换分类，点击图片看大图。

**修改密码（前台 + 后台）**
- 登录后，前台顶部（视觉专区 `index.html` / 趋势专区 `trends.html`）与后台（`admin.html` 顶栏）均有「修改密码」入口，点击弹出密码修改窗口。输入旧密码 + 新密码（至少 6 位）+ 确认新密码即可完成修改；修改需**先填写正确的旧密码**（系统会重新校验），成功后使用新密码登录。普通用户与管理员均可使用，无需额外数据库部署（走 Supabase 内置认证）。

**后台（管理员）**
- 打开 `admin.html`，管理员账号登录。左侧菜单为独立面板（无序号前缀）：图片管理、标签管理、数据看板、趋势专区、招品回品、BESTSELLER。**各菜单面板相互独立**，点哪个只显示该菜单内容，进入后台默认只展示当前菜单，不会连在一起。上传图片功能已并入「图片管理 → 智能打标」弹窗内。
- **招品回品 · 上传/图片匹配（先传表格单入口）**：招品回品面板上传区已重做为**「先传表格」**唯一入口。①上传**招品表格**（8 列：`任务ID | 站点id | 行业链接 | 开款优先级 | 开款类型 | 招品原因 | 提需时间 | 首图URL`）；②系统解析后自动分流：**带「首图URL」的行**直接生成任务卡片、无需再传图；**没有「首图URL」的行**需用「②站内类目 + ③补充图片」上传**文件名=任务ID** 的图片（一个任务一张图，按文件名匹配到对应的缺图任务）；③选好所属**类目**后点「导入并生成任务卡片」。上传区保留**进度显示**与**清除已选表格/图片**。**前台任务卡片**展示：**站点名**（按站点映射表把 `站点id` 显示为站点名）、**提需时间**（只展示到日）、**开款优先级**、**招品原因**、**类目**（形如`类目：XXX`）；**点击图片**若有「行业链接」则新标签页跳转。**后台任务卡片图片**右上角显示**可复制的任务ID**（点击复制）。
- **后台审核标记（招品回品 / BESTSELLER）**：两张任务卡片图片右下角提供「IP / 品牌 / 类目错放 / 无需回品」四个勾选框，勾选即打标记（仅后台可见，前台不展示）。面板顶部有**标记统计图表**（可按类目筛选，展示各标记的数量与占比），并在其下方提供**状态统计条**（全部 / 已发布 / 商家已上传 / 已回品 / 无需回品 各数量，口径与状态筛选按钮一致）；工具栏提供**按标记筛选**；**导出 Excel** 会包含「类目 / 标记 / IP / 品牌 / 类目错放 / 无需回品」字段。状态筛选按钮文案统一为「全部 / 已发布 / 商家已上传 / 已回品 / 无需回品」。新库需执行 `tools/setup.sql` 或单独执行 `add_task_flags.sql` 以创建 4 个标记字段（`flag_ip/flag_brand/flag_cat_mismatch/flag_no_refill`）。
- **超管权限**：侧边栏「超管权限」为超级管理员专属菜单（普通管理员不可见），收拢全部超管专属功能，内含五大功能区块：**公告管理**（编辑/发布/下架/删除公告，前台登录后展示近一个月未读公告）、**权限管理**（设置用户角色、按类目分配管理员可管理的类目权限、为每个用户单独配置「用户级可见专区」，并提供「用户权限分配表」总览所有用户的角色/类目/专区授权，以及**登录设备**和**登录 IP**——取每个用户最近一次登录记录，登录时由前端自动采集浏览设备/系统与公网 IP 存入 `login_logs` 表）、**前台访问设置**（公开浏览开关、各专区各类目前台可见性开关）、**数据导出**（按前台筛选条件导出 Excel，含图片与分类标签）、**存量图片压缩池**（左池＝已压缩 ≤200KB，右池＝待压缩 >200KB；可在右池单选/多选/全选批量压缩，压缩自动转为 WebP 并压到 200KB 以下，完成后自动跳入左池；单张可点「预览」检查清晰度、点「转WEB」强制转 WebP；带进度显示）。前台类目展示顺序仅超管可在「标签管理 → 展示顺序」处调整。
- **预览前台**：后台顶部「预览前台」按钮，点击弹出内嵌预览窗口，**实时加载前台页面，无需另开浏览器标签页**即可查看前台效果（改完标签/类目/公告或上传新图后直接预览）。预览窗顶部可切换**视觉专区 / 趋势专区 / 招品回品**，并提供「刷新」（改动后即时重新加载最新内容）、「新标签打开」、「关闭」，支持 Esc 键关闭。
- **上传（在「图片管理 → 智能打标」弹窗内）**：打开图片管理 → 点「智能打标」进入弹窗，在右侧「上传图片」区选择类目 → 拖拽/点击多选图片 → 点「上传」。图片经 Worker 写入 R2，清单记录进数据库，前台立即可见。**上传自动去重**：与库中同名图片会被跳过，不会重复上传。**上传自动转 WebP**：大图在浏览器端自动转成 WebP 格式（最长边约 1600px、WebP 质量 0.82），同观感但体积更小，显著减小占用、加快前台（尤其是手机端）加载；小于 300KB 的小图**不转换**、保留原图；转码不划算或失败时自动回退原图，绝不丢图。
- **批量匹配外链（可选）**：选好图片后，点“上传Excel匹配链接”，上传含 `Name`（图片名，**不含扩展名**）+ `Url`（外链地址）两列的 Excel/CSV，系统按图片文件名自动给待上传图片挂上外链；待传列表里已匹配图片会显示「🔗 已匹配链接」。上传时外链随图片记录一起入库。**前台灯箱**：点击图片打开大图后，若该图有外链，会显示「🔗 打开链接」按钮，点击在新标签页打开跳转；无外链的图不显示该按钮。
- **管理**：按分类查看图片；支持批量删除（同时删 R2 文件与清单）；**勾选多张图 → 点“批量打标签”**，分渠道/风格/元素/场景/拍摄方式/肤色统一打标（添加/移除/清空）。

**六维标签（渠道 / 风格 / 元素 / 场景 / 拍摄方式 / 肤色）**
- **渠道标签**（固定清单，后台不可增删）：市场站（TEMU / AMAZON / ALIEXPRESS）、社媒（TIKTOK / INS / FACEBOOK）、灵感（PINTEREST）、品牌网站（SHEIN）。清单在 `js/config.js` 的 `CHANNEL_TAGS` 维护。
- **风格 / 元素 / 场景 / 拍摄方式 / 肤色标签**（后台可自定义增删）：在后台「标签管理」中新增/删除，删除时会同步移除所有图片上的该标签；首次建库会自动预置常用标签（`PRESET_*_TAGS`）。
  - **标签搜索**：标签管理区顶部有搜索框，按名称实时过滤所有维度的标签。
  - **新增置前**：新增的标签自动排在所属维度列表最前面。
  - **改名**：每个标签悬浮可见「改名」按钮，改名后**同步更新图片上已打的该标签**——覆盖全部维度（风格 `style_tags`、元素 `element_tags`、场景 `scene_tags`、拍摄方式 `shoot_tags`、肤色 `skin_tags`、渠道 `tags`、类目 `category`）。**智能打标**弹窗内的顶部标签栏与图册栏也支持改名，同样走这套同步。改名只更新打了该标签的图片，未打该标签的图不受影响；前台无本地标签名缓存，刷新后即显示新名字，无需重新打标。
  - **场景二级分组**：场景标签分「室内 / 室外」两大二级分组（数据库 `tag_defs.group` 字段 `indoor/outdoor` 作为真实分组依据，**不依赖命名**）；新增时先选大类再填场景名（不用带前缀）；前台筛选、后台标签列表、数据看板均按室内/室外分组统计。
  - **类目删除**：前台类目管理列表会并入图片中实际出现的类目（含误加未入库的残留如「露脸模特」），每项右侧有「删除」按钮，删除会同步清空该类目下图片的类目字段。图片管理左侧类目菜单里，对「不在配置表中的残留类目」也会显示一个红色「×」按钮，可直接一键删除（清空该类目下所有图片）。
  - **传图不新增类目**：上传图片时只能从已配置的「前台类目 + 常用类目」下拉里选择，**不再支持在传图时新建类目**，防止误传/误加出残留类目；如需新增类目请到「标签管理 → 前台类目」添加。
  - **常用类目与前台类目完全一致**：两者双向同步，任一面板新增/删除都会同步到另一处。在「常用类目」勾选保存＝同步写入/移除「前台类目」；反之在「前台类目」保存/删除也会同步更新「常用类目」，始终保证两个列表完全相同。
- 预设值：
  - 拍摄方式：摆拍 / 挂拍 / 模拍 / 3D
  - 肤色：黑 / 白 / 黄
  - 场景：分「室内 / 室外」两大类，前台按组展示（如 室内·卧室、室外·街道）
- **批量打标**：后台「图片管理」勾选多张图片 → 点「批量打标签」，可分别按任意维度添加或移除标签，也可一键清空。
- **智能打标**：后台「图片管理 → 智能打标」，进入某个维度后图片池自动聚焦**该维度尚未打标**的图片，方便直接挑选未打标的图。
- **前台展示与筛选**：视觉专区顶部有**吸顶的标签筛选栏**（各维度分组，向下滚动仍始终可见），可多维度组合筛选；图片标签改为**鼠标悬浮显示**——把鼠标移到某张图上才浮出该图的所有标签，移开即收起，图片下方不再常驻标签。
- **前台展示开关**：后台「前台访问设置 / 标签管理」可为**每个标签维度单独控制是否在前台展示**。关闭某维度后，前台筛选栏不再显示该维度分组、图片悬浮标签也不显示该维度，前台不可见。
- **各专区 · 各类目 · 前台可见**：后台「前台访问设置」可为**视觉专区 / 趋势专区 / 招品回品 / BESTSELLER** 四个专区的**每个类目单独开关前台可见性**。关闭某专区某类目后，前台该类目下内容立即隐藏（用户看不见），不影响后台数据；可随时重新开启。未配置的类目默认前台可见。
- **前台类目展示顺序**：仅**超级管理员**可在后台「标签管理 → 展示顺序」调整前台类目的展示顺序，普通管理员不可见此设置。
- **图片比例**：前台图片网格固定为 **1340:1785（3:4 竖版）** 比例，图片完整显示、不被裁成方形。
- **数据看板**：后台「数据看板」实时统计各维度标签下的图片数量（横向条形图）、打标覆盖率（环形图）及图片总数/类目数/已打标/未打标总览。

> **升级旧站点**：本版 `tools/setup.sql` 新增 `images.tags`（渠道）、`images.style_tags`（风格）、`images.element_tags`（元素）、`images.scene_tags`（场景）、`images.shoot_tags`（拍摄方式）、`images.skin_tags`（肤色）六列、`images.url`（图片外链，供前台灯箱「打开链接」跳转）一列，以及 `categories`、`site_settings`、`tag_defs`（标签定义表）、`site_settings.frontend_dims`（各维度前台展示开关）、`site_settings.frontend_cat_visibility`（各专区各类目前台可见性开关）与匿名读取策略。已上线的库请把 `setup.sql` 整体重跑一遍（全部为幂等语句），并把 `worker/worker.js`（修复版，兼容中文路径 + 公开模式放行）重新部署到 Cloudflare Worker。

**为访客建号**
- 默认开放自助注册（`config.js` 的 `enableSignup` 控制）。要改为仅管理员建号：设 `false`，在 Supabase **Authentication → Users** 手动 Add user。

## 四、常见问题

- **登录提示 Invalid login credentials**：密码错误，或邮箱未在 Auth 用户里。
- **看图 401**：登录态过期，重新登录即可（Worker 会校验令牌）。
- **上传提示无管理员权限**：确认当前账号已在 SQL 里升级为 admin。
- **上传/看图报 404**：Worker 的 R2 Binding 变量名必须叫 `IMAGES`，且绑定到 `images` 桶。
- **前台能看图但类目菜单为空/不全**：前台图片清单与类目菜单都必须走免权限函数（`frontend_list_images` 看全部图、`frontend_list_used_cats` 看全部图片类目）。若菜单只剩「全部」，说明 `frontend_list_used_cats` 函数未创建，或线上 `js/supabase.js` 仍是旧版（直接查 `images` 表、受后台 RLS 限制，普通管理员/访客只看到自己上传图的类目）。在 SQL Editor 执行 `tools/setup.sql`（或单独建该函数）并覆盖最新 `js/supabase.js` 即可。
- **为什么要 Worker 而不是直接放桶**：R2 桶保持私有，任何请求都要 Worker 校验令牌，未登录无法拿到图片，实现”真私密”。

## 内容防爬 / 防复制（本版新增）

- **下载水印**：前台图片「观看无印、下载带水印」。页面展示仍为无水印原图；当用户触发下载（右键等）时，前端用 canvas 重新绘制，叠加两处半透明水印——
  - 顶部居中：`图片来源网络 · 仅供参考学习`
  - 右下角：`newtrend.top`
  - 覆盖视觉专区（js/frontend.js）与趋势专区（js/trends.js）；拖拽、Ctrl+S、长按仍禁用。
- **图片表匿名读收紧**：已移除 `images` 表的匿名读取策略（原 `anon read images`），未登录用户不再能读取图片清单/元数据，需登录后经登录态策略读取。可用脚本 `restrict_images_anon.sql` 在 Supabase SQL Editor 一键执行（旧库也适用）。
- **图片读取限流 + 审计**：图片服务按来源 IP 做窗口限流（每 IP 每分钟 120 次，超限返回 429 并打印审计日志），用于防脚本化批量拉取，正常用户零影响。

> **部署**：覆盖仓库 `js/frontend.js`、`js/trends.js`、`worker/worker.js` 并重新部署图片服务；执行 `restrict_images_anon.sql`（或重跑 `tools/setup.sql`，均为幂等）；前台强刷。
